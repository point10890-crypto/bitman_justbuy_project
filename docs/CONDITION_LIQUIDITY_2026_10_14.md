# 섹션별 거래대금 필터

사용자가 승인한 초기 유동성 설정이다. 수익률 우위가 검증된 전략 수치로 해석하지 않는다.
기존 기술·수급·위험 제외 규칙을 유지하며 거래대금을 추가 확인한다.

| 섹션 | 최소 조건 | 정렬 가점 |
|---|---|---|
| 단타 | 당일 100억 | 300억 이상 +5 |
| 스윙 | 직전 20거래일 평균 50억 | 당일 100억 이상 +5 |
| 주도주 | 직전 20거래일 평균 200억 + 당일 500억 | 당일 1,000억 이상 +5 |
| 테마주 | 당일 100억 | 300억 이상 +5 |
| 종가매매 | 당일 100억 | 300억 이상 +5, 500억 이상 +10 (합산하지 않음) |

단타·테마주는 KST 09:00~09:59에 30억, 10:00~10:59에 50억으로 최소 조건만 낮춘다.
주도주는 같은 시간대 각각 150억·250억이며 평균 200억 조건은 유지한다.
종가매매에는 장 초반 완화를 적용하지 않는다. 정렬은 기존 점수 + 거래대금 가점이며
기존 ruleScore/aiScore/finalScore 값은 수정하지 않는다. 거래대금 정렬 가점은 근거 문장에 표시한다.

## 데이터와 누락 처리

- 기존 KIS 읽기 전용 일봉 API `inquire-daily-itemchartprice`의 `acml_tr_pbmn`(원)을 사용한다.
- 종목코드, 응답 상태, 조회 시각, 일봉 날짜·중복을 검증한다. 현재가 × 거래량은 대체값으로 사용하지 않는다.
- 당일을 제외한 직전 20거래일을 모두 확인해야 평균을 계산한다. 19일·날짜 공백·누락 거래대금은 평균 미확인이다.
- 장전·휴장일은 프로젝트 거래일 달력의 직전 거래일 완료 일봉을 사용하고, 전체 거래대금 기준을 적용한다.
- 장중은 현재 거래일 일봉이 있어야 한다. 이전 거래일 거래대금을 당일로 사용하지 않는다.
- 성공·미확인 조회 모두 60초, 최대 500종목 캐시. 후보별 요청은 기존 KIS 인증·호출 제한을 공유한다.
- 후보 묶음당 최대 30종목, 조회 예산 15초. 예산 내 확인하지 못한 후보는 통과시키지 않는다.
- 동일 시간대 20일 평균 2배, 눌림 대비 증가, 업종/테마 거래대금 순위, 마지막 30분 증가의 비교 자료는 이 일봉 응답에 없다.
  해당 조건은 확인했다고 표시하지 않으며 추가 가점을 주지 않는다. 절대 거래대금 가점과 구분한다.

## 적용 경로

- `MainConditionService`: 홈·섹션 상세·미리보기·알림의 모든 5개 섹션. 실시간·캐시·대체 엔진 응답도 공통 게이트 적용.
- `ShortTermRealtimeScanner`: 최대 30후보를 거래대금으로 거른 뒤 TOP3를 선정하고, 통과한 후보의 포착 시각만 저장.
- `LeaderConditionEngine`: AI 검증 대상 선정 전 최소 거래대금 확인.
- `AnalysisService`: 단타·스윙·주도주·테마주의 신규 AI 결과와 기존 캐시 조회. 공개 텍스트·종목목록·합의 결과를 함께 필터링.
- 종가매매 홈 후보는 V2 신호를 최대 30개까지 읽은 뒤 같은 게이트 적용. 과거 V2 원본 파일·히스토리 API와 Python 연구 엔진은 변경하지 않음.
- 검색 파이프라인 설명 API에 `liquidityRules`, 금액 단위, 장 초반 기준을 추가.
- 모든 후보가 미달/미확인이면 홈에는 빈 목록과 `LIQUIDITY_UNCONFIRMED` 상태를 반환한다. AI 경로에서 먼저 빈 결과가 되면 기존 EMPTY 상태를 유지한다.

## 검증 범위

외부 KIS/AI 호출 없이 고정 일봉 응답으로 최소값 경계, 시간 경계, 당일 제외 평균,
누락·잘못된 종목코드·미래/오래된 조회, 가점 정렬, 중복 가점 방지, 캐시 재사용,
홈 5개 경로와 알림, AI 공개 결과, 포착 시각 회귀를 검증한다.
실거래 데이터 품질·장중 공급 지연·전략 성과 및 운영 배포는 별도 검증 대상이다.
