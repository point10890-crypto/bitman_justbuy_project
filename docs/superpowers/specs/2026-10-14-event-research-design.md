# BitMan public event research

The user approved sequential implementation, testing, commit/push/deployment and final runtime verification on 2026-10-14. This specification records the approved six-layer design and the buyback follow-up. Proceed in the current task without another permission cycle.

## Delivered behavior

An independent Spring service discovers named customer/supplier relationships from actual DART supply-contract originals, records immutable first-seen evidence, calculates explicitly labelled profit scenarios from verified financial statements, challenges them, obtains KIS/Kiwoom market evidence, and exposes research observations in the paid app. Supplier candidates originate from disclosure identities, never LLM-invented tickers. A relationship can be discovered by a new contract; using it to propagate an earlier customer event is prohibited. Unknown counterparties, amendments without previous amount, missing unit/period, and unverified price remain unknown. Observations do not claim proven trading advantage and initially do not overwrite existing rankings.

Existing ResearchOutcomeEvaluator/ResearchLearningService are offline libraries. Runtime capture and persistence must be added; supported fixed horizons are 1/3/5/20 sessions. Publication-time observations and next-session-open simulations are different. A closing snapshot is stamped at the actual research publication time after 15:30; historical DART dates are not intraday timestamps. Outcome collection only reads completed bars, uses the KRX calendar, and does not synthesize future data. Annual revenue/profit are historical proxies, not product-specific future margins or quarterly totals. Missing costs means net=null. Missing benchmark means excess=null.

## New boundaries and contracts

Package `com.bitman.justbuy.research.event`:

- `DartSupplyContractSource`: bounded dedicated HTTP client using DartProperties; `fetchRecent()` returns a Snapshot(status,capturedAt,contracts,issues). `Contract` contains supplierCode,supplierName,customerName,product,amountWon,previousAmountWon,recentSalesWon,startDate,endDate,filingDate,receiptNo,sourceUrl,firstSeenAt,amendmentStatus,evidenceText,documentHash. DART list max 3 pages of 100, originals max 12 per refresh; timeout and global elapsed budget; never log key-bearing URLs or exceptions. Original ZIP/XML is size bounded with external entities disabled. Cancelled/amended contracts must not count as fresh incremental orders. Cached successful originals reused by receipt number. Collect explicit notes and coverage limits.
- `CashImpactCalculator`: pure BigDecimal code; nested input/scenario/result types. Separates observed values from assumptions. Margin ranges, supplier allocation and period recognition are explicit assumptions. Cash flow remains unknown when tax/cash-conversion/working-capital/capex inputs are missing. Includes negative contract delta and capacity/period invalidation. No arbitrary score for a disclosure title.
- `EventEvidenceVerifier`: structured fact-bound challenge via existing AiAgent DeepSeek where available; validation checks subject, quoted facts, units, provenance, time and scenario-vs-observation. Deterministic contradictions run even when AI unavailable. Timeout/refusal/invalid output retain RULE_ONLY status, never count as AI verification or consensus.
- `EventResearchPipeline`: single-flight asynchronous refresh; versioned durable latest snapshot and case history in an owned separate research directory under configured data-dir. Atomic file replacement, bounded storage and candidate count, immutable evidence, no member DataSource. Failed refresh retains prior successful snapshot with stale/error status. API GET does not trigger external calls. Stage results reused when unchanged. Scheduler periodically refreshes and performs actual outcome capture without Telegram messages. Runtime status reports source coverage and pending outcomes honestly.
- `KindBuybackSource`: next-day applications and daily executions from public official KIND listings; origin/URL allowlist; KOSPI/KOSDAQ formats and money units distinguished; matching only report days available before cutoff; historical fulfilment and expected participation derived with window/count disclosed. Application is never actual execution or a guaranteed support price. No arbitrary current URL/fixture in production.

Read-only paid endpoint `GET /api/research/events` and admin `POST /api/admin/research/events/refresh`, `GET /api/admin/research/events/status`. Reuse SubscriptionAccessGuard; no unauthenticated leak of paid candidates. Safe metadata-only `GET /api/research/events/status` is public for operational verification. Existing analysis/condition DTOs remain compatible. Existing swing/leader cards link to the independent research view; no unproven auto-promotion.

Frontend: a home link and `/research/events` route, source-backed observation cards with customer/product/original/first-seen/financial reference/scenario assumptions/counterarguments/price environment/outcome state. Empty, loading, partial, stale, auth and subscription failures explicit; no sample stock fallback. Admin can refresh; user view only fetches stored results. SW version changes.

## Completed implementation choices

Customer propagation requires the customer's official filing date to be strictly later than the KST relationship discovery date. Date-only same-day ordering is unproven. Known expired or not-yet-started contracts are excluded; unknown validity remains labelled. An unresolved later amendment blocks prior issuer/customer exposure even if its product name changes; an unknown-customer withdrawal conservatively blocks prior issuer exposures. Later confirmed originals can establish a new observation.

Initial publication, input facts, assumptions and price context are frozen. Subsequent market queries are separately stored as `currentMarket`; they cannot change an earlier publication or its returns. Failed AI stages reuse the frozen result and original cutoff, with at most two potential provider calls per run and three per case. AI input fidelity is reported separately from profitability.

Within one analysis-policy version, case identity uses canonical observed contract fields and evidence plus the financial disclosure receipt. Download ZIP packaging, raw archive hash and lookup/capture timestamps do not create a new case. The original raw ZIP hash remains frozen as provenance. Material contract/evidence or financial-receipt changes create a new revision. A policy version change records a genuine new-policy publication without relabelling earlier policy results or backdating its cutoff; earlier cases and their observations remain immutable.

If the current financial lookup is unavailable and provides no verified new financial receipt, retain the latest verified case for the same current-policy contract fingerprint. Original financial facts, scenarios, publication, evaluation and original market context remain frozen; current market and current source coverage are separate. Do not use a different contract fingerprint, old policy, future publication or unverified financial packet as fallback. An initially unknown case becomes a separate revision when a genuine financial disclosure is first obtained.

First-seen records are stored in disclosure-day shards and publication proofs in per-case files; there is no lifetime 5,000-receipt/500-case write cutoff. Legacy records remain readable and corrupt chronology indexes fail closed. Stored files are preserved. The supplier relationship window is the latest 500 cases with an explicit coverage flag; outcome processing also retains incomplete cases within 60 days of their actual evaluation anchor. Temporary missing bars are retryable; confirmed measurements survive later source outages.

Existing `REVERSAL_EDGE` top-three and eligible event observations are captured after the close into separate, immutable daily portfolios with equal weights and explicit cash remainder. The positive-weight union must have completed real KIS bars before a comparison is measurable. Entry session counts as session one; each horizon exits at that session's close. Cost assumptions are frozen at capture; unverified costs produce gross-only comparisons. At least 30 independent cost-qualified dates are required by the existing learning review, with no automatic production activation. Calendar coverage is confirmed only through 2026; a horizon crossing beyond it is unmeasurable until official coverage is extended.

KIND execution parsing uses actual official table headings: KOSDAQ execution reports omit the application column and quote won, while KOSPI reports quote thousands of won. Missing application denominators are matched to the exact same market/ticker/category/report day. At most three report days and 80 display rows (40 per market) are collected; estimates remain historical scenarios. Both application and execution originals are linked.
