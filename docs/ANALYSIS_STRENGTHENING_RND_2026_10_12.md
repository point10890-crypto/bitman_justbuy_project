# 분석 파이프라인 강화 연구·개발 — 2026-10-12

## 목표와 현재 범위

추가 모델 수보다 실제 자료의 기간·통화·출처·정정 여부를 확인하고, 그 자료가 분석 판단에 사용되도록 만드는 것이 우선이다. 무료·저비용을 우선하며 KIS를 주 소스로, 키움 REST를 독립 보조 소스로 유지한다. MOCK 조회의 실제 공급자·환경은 그대로 표시한다.

이 문서는 공식 자료 조사와 구현·검증 기록이다. 아래 운영 검증 항목은 실제 확인 결과로 갱신한다. 분석 근거의 확장은 수익률 개선의 증명이 아니다.

## 코드 감사로 확인한 공백

- KIS·키움 완료 일봉에는 기본 이동평균·돌파·거래량 근거가 있지만 Spring 분석 입력에서 같은 기준의 수익률·변동성·ATR 근거가 부족하다.
- 기존 DART 주요계정은 계정명과 당기금액 중심이다. 분기순이익/기말자본을 기간 설명 없는 ROE로 표시하고, 재무 점수는 공시 제목 단어에도 가점을 준다.
- 정기 분석의 DART 조회는 질문에 명시된 종목 중심이므로 일반 후보 재무근거가 AI 입력에서 빠질 수 있다. 최종 카드 단계의 별도 조회는 지연과 중복 호출을 만든다.
- DeepSeek 전문 역할이 없고, 조건검증 출력의 개별 수치가 입력 원값과 일치하는지 프로그램에서 직접 확인하지 않는다.
- 성과 기록은 존재하지만 당시 구조화 근거와 규칙 버전 보존이 부족하다. 현재 합의 점수는 검증된 성공 확률이 아니다.

## 이번 구현 계약

1. **DART 전체 재무 도구**: 기존 인증키와 회사코드 캐시를 사용한다. 연결/별도·계정·통화·보고서 기간을 검증하고 현금흐름·동기간 비교를 구조화한다. 자료 없는 값은 만들지 않는다. 다섯 후보와 실행 예산 안에서 조회하고 AI와 카드에서 재사용한다. 제목 키워드 가점과 무기간 ROE를 제거한다.
2. **공통 기술·위험 도구**: 이미 받은 완료 수정주가 일봉에서 20/60 거래일 수익률, ATR14, ATR 비율, 20일 역사 변동성을 계산한다. 추가 시세 호출·외부 라이브러리·자동 점수 가중치 변경은 하지 않는다. 종목/벤치마크의 날짜가 맞지 않은 상대강도는 산출하지 않는다.
3. **증거 품질·반증 도구**: 기존 DeepSeek 역할에 반증 검증을 지정한다. 주장별 원사실 식별자와 값의 일치를 검사하고 입력 밖 숫자, 종목·기간·출처 치환을 차단한다. 검사 실패는 해당 후보의 기존 규칙 판정으로 폴백한다. 새 모델 호출은 없다.
4. **시점별 근거 감사 기록**: 회원·키·질문 원문을 보존하지 않고 분석 후보, 구조화 사실, 버전, 단계별 판정을 제한된 로컬 저장소에 보존한다. 기록 장애는 분석을 중단하지 않는다. 이를 완성된 백테스트나 성과 학습이라고 부르지 않는다.

각 구현은 의미 있는 실패 테스트를 먼저 확인하고, 전체 회귀 검증과 코드 리뷰를 거쳐 커밋·푸시·표준 MiniPC 배포·운영 확인 순으로 진행한다. 운영 계정과 키는 변경하지 않는다.

## 에이전트·도구의 후속 순서

- 이번 세 가지 사실 계산/검증 도구를 기존 AI 입력에 연결한다.
- 이후 지분·기업관계·뉴스 이벤트를 접수번호/발생일/기업 식별자로 묶어 중복과 반증을 관리한다.
- 같은 완료 거래일의 시장 ETF와 후보를 비교하는 상대강도를 확장한다. ETF는 시장 지수의 프록시이며 후보 일부의 시장 폭을 전체 시장으로 표시하지 않는다.
- 감사 스냅샷을 충분히 모은 다음 실제 1/3/5일 결과·벤치마크·비용을 연결해 시간 순서 검증을 한다. 규칙 단독과 AI 혼합, 기존/개선 버전을 동일 표본에서 비교한다.
- 성과 기반 학습·가중치 조정·RAG는 이 검증 이후 적용한다. 기존 DB 검색을 먼저 사용하고, 전문 검색 또는 Ragas 같은 평가 도구의 추가 LLM 비용은 별도로 계측한다.
- 최신 ta4j는 현행 요구사항과 Java 21 호환성을 확인해야 한다. 이번에는 기존 Java 계산을 확장해 의존성 비용을 만들지 않는다.

## 실제 검출 종목 품질 평가

2026-10-12 운영 MiniPC에 저장된 네 AI 모드의 공개 종목·가격·출처만 추출했다. 회원 DB와 질문 원문을 사용하지 않았다. 당시 단타·주도주 별도 실시간 스캐너 및 전체 종가 시그널은 이 9건 표본에 포함되지 않으며, 종가 성과 계산은 별도 코드·화면 검증으로 확인했다.

- 저장된 9건은 팬오션·HMM·DB손해보험·삼표시멘트 4개 종목이다. 팬오션 4건과 HMM 3건으로 7/9건이 두 종목에 집중되어 있다. 모드 간 중복 자체는 오류가 아니지만 독립된 투자 후보 9개로 계산해서는 안 된다.
- 목표·손절 방향은 모두 현재가 위/아래이나 4건은 목표 상승 폭보다 손절 하락 폭이 크다. DB손해보험 스윙 0.38, 팬오션 스윙 0.71, 삼표시멘트 테마 0.85, HMM 스윙 0.91이다. 이 비율은 AI 표시 가격 간 거리이며 실현 기대수익·승률이 아니다.
- 기존 성적표 최근 30일 표시 평균 수익률은 다섯 모드 모두 음수(-0.98%~-1.76%), 승률 36%~43%였다. 과거 기록은 보유기간·기준가·현재 표시와 정의가 혼재되어 이번 개선의 효과 검증 표본으로 사용할 수 없다.
- 홈의 새 완료 5거래일 실측 성과는 당시 0건이다. 이번 변경 이후 동일 기간·벤치마크·비용의 실측 표본이 쌓이기 전에는 수익률 개선이나 예측 정확도 향상을 주장할 수 없다.

공개 원자료는 `DETECTED_STOCK_QUALITY_SNAPSHOT_2026_10_12.json`, 기존 화면 수치는 `DETECTED_STOCK_LEGACY_PERFORMANCE_2026_10_12.json`에 보존했다. `node docs/evaluate-detected-stock-quality.mjs`는 내장 SQLite의 명시적 SQL로 9건/4종목/4건 비율 미달을 재계산한다. `DETECTED_STOCK_QUALITY_REPORT_2026_10_12.artifact.json` 보고서는 검증 후 Codex 보고서 패널에 렌더링하고 실제 표시를 확인했다.

## 구현된 운영 점검과 한계

- 관리자 시스템 상태에서 저장 픽의 시세 출처·시점, 분석 참여·이견, 실제 재무 계정 유무, 중복과 AI 목표·손절 표시의 한계를 확인한다. 이 화면 조회는 새 공급자·AI 호출을 만들지 않는다. 근거 부족 또는 오래된 자료를 검증 완료로 승격하지 않는다.
- 별도 버튼으로 한 종목의 DART 전체 재무만 조회한다. 최대 다섯 종목/실행 10초 예산, 연결 2초·읽기 3초, 양성 캐시 24시간·음성 30초와 인증·한도 오류 휴지기를 적용한다. 오류 본문 drain이 지연을 만드는 HTTP close 경로도 실제 factory 회귀로 확인한다.
- 종가 히스토리는 실제 추적 기준 가격을 표시한다. 미검증·검증불가·검증 완료를 구분하고, 기준가격 없음 또는 일일 가격 기준 불일치를 통계에서 제외한다. 과거 회원·추천 DB를 수정하거나 누락된 과거 값을 만들어 넣지 않는다.
- 공개 구조화 근거 감사는 큐 64, 파일당 1MiB, 관리 파일 1,000개/30일로 제한한다. 원문 질문·키·회원 정보·자유 서술을 저장하지 않는다. 이것은 제한된 감사 기반이며 완성된 재현 백테스트·성과 학습 시스템은 아니다.
