# KIS·키움 20종목 교차 조회 및 운영 안정성

사용자 요청에 따라 기존 최대 3종목 교차 조회를 최대 20종목으로 확장한다. 기존 KIS 후보·가격·수급을 유지하면서 키움 시장 조회를 함께 사용한다. 전 시장을 모두 검색하거나 HTS 저장 조건식을 신규 연결하는 변경은 아니다.

## 호출 제한과 실제 연결

- 키움 공식 안내는 국내주식 REST 전체 초당 5회, 모의투자에서는 TR별 초당 1회를 명시한다. 이번 구현은 더 보수적으로 MOCK 전체 1회/초(최소 1,010ms), REAL 전체 5회/초(최소 210ms)를 유지한다. OAuth와 모든 조회 TR가 같은 제한기를 사용한다.
- ka10095는 여러 종목코드를 `|`로 전달하는 공식 다중종목 조회다. 20은 앱의 후보 제한이다. 공식 조건검색 결과 최대 100종목을 ka10095의 입력 한도로 해석하지 않는다.
- 2026-10-12 14:21 KST MiniPC에서 BitMan 전용 MOCK 인증으로 ka10095에 20종목을 요청했다. return_code=0, 반환·고유 종목·양수 가격 검증 모두 20건, 누락 및 예상 밖 코드 0건이었다. 키·토큰·응답 전문은 기록하지 않았다.
- MOCK이라는 인증 환경명만으로 실제 시장 조회를 차단하지 않는다. 출처 `KIWOOM_REST_MOCK`과 서버 환경을 보존한다. REAL 정보이용 확인 플래그는 변경하지 않는다. 주문·계좌 API는 사용하지 않는다.

공식 근거: [사용 안내·호출 제한](https://openapi.kiwoom.com/intro), [키움 공식 API 명세](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/kiwoom/_data/kiwoom_api_spec.json), [오류 정의](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/kiwoom/core/errors.py).

## 구현과 장애 격리

- 키워드 검색과 4개 AI 모드, 독립 단타·주도주 스캐너의 키움 후보 상한을 20으로 확장한다. 단타·주도주도 게시 TOP3를 고르기 전 후보에서 근거를 수집하고 같은 실행 안에서는 준비한 조회 배치를 재사용한다. 기존 KIS 상세 분석 예산은 유지한다.
- 키움 현재가는 한 번의 다중종목 조회로 수집한다. 종목별 20초 캐시를 공유해 겹치는 검색의 중복 조회를 줄인다. 원 조회시각을 유지하고 신선도·코드·이름·단위 검증을 다시 적용한다.
- 키움 전경 응답 예산은 12초다. 시세·기본정보·완료 일봉·확정 일별 수급 중 미확인 자료는 단일 백그라운드 작업자로 수집한다. 작업은 중복 제거, 최대 128건, 요구 후 120초 만료를 적용한다. 이전 완료일 작업은 거래일 경계가 달라지면 실행하지 않는다.
- 키움 원응답 캐시 최대 1,024건, 종목 시세 캐시 최대 256건을 적용한다. 원응답은 만료 항목부터 정리하고 필요하면 기존 항목을 제거한다. 종목 시세는 원 조회시각이 가장 오래된 항목부터 제거해 용량을 넘기지 않는다.
- KIS 시세도 최대 20개 후보를 공유 캐시와 단일 작업자로 확인한다. 대기열 최대 40건, 캐시 최대 512건이다. 첫 검색은 앞쪽 후보의 확인을 총 1.5초까지만 기다리고 나머지는 대기로 표시한다. 기존 KIS 공통 호출 제한기를 그대로 사용한다.
- HTTP 429 및 키움 1700·1701·1702 제한 응답은 30초 호출 휴식을 적용한다. 연속 3회 장애도 30초 쉬며 실패는 5초 동안 재요청을 억제한다. 인증 실패는 토큰을 무효화하고 인증 재시도를 제한한다. 무한 자동 재시도는 없다.
- 공식 SDK의 인증 복구 코드 8005·8031·8103은 HTTP 200 본문 또는 메시지 내 코드여도 토큰을 폐기한다. 30초 휴식 후 다음 실제 요청에서만 재발급한다. 실전·모의 키 불일치 8030과 IP 설정 오류 8010은 재발급 루프에 넣지 않는다. 이 결함은 수정 전 5개 사례 모두 실패, 수정 후 통과로 재현·검증했다.
- 대기열 등록 실패와 이미 확인된 자료를 미확인 대기 수에 포함하지 않는다. 작업 예외는 다음 작업과 분리하고 서비스 종료 시 대기열·작업자·대기 Future를 정리한다.
- 수집 중인 값은 `PENDING`이며 수치·조건 충족으로 생성하지 않는다. 공급자 하나가 실패해도 이미 검증된 다른 자료를 보존한다. 두 공급자의 가격을 평균하거나 수급을 합산하지 않는다.
- 사용자 화면은 공급자별 요청·확인·대기 종목 수와 실제 출처를 표시한다. 자동 폴링을 추가하지 않고 사용자 재검색에서 갱신 자료를 사용한다. 관리자 시스템 상태에 제한 속도·대기열·작업자·캐시·최근 성공 시각을 안전한 필드만 표시한다.
