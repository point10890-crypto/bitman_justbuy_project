## 조회 범위와 데이터 의미

- 현재 앱의 숫자 6자리 종목코드 계약을 유지한다. 공개 마스터 실제 검증에서 3,540개 식별과 제외 대상 1,182개를 확인했다. 영문이 포함된 코드 등은 포함하지 않으므로 전체 상장시장 검색이라고 표시하지 않는다.
- 원본 줄바꿈을 제외한 마스터 꼬리 길이는 KOSPI 227바이트, KOSDAQ 221바이트다. 공식 샘플의 228/222에는 LF가 포함된다. CP949 바이트 단위로 파싱한다.
- 업종 파일 491행 중 비숫자 키 5행과 빈 이름 1행은 미분류로 남겨 PARTIAL 상태로 표시한다. 숫자 업종 코드를 업종명으로 추정하지 않는다.
- 마스터 TTL 24시간, 다중 시세 캐시 30초. HTS·순위·마스터 후보는 최대 600종목이며 전체 시장을 보장하지 않는다. 원 거래시각이 없으면 조회 시각으로 대체하지 않는다.
- 기술/PER/PBR 조건은 시세 조건 통과 후 정렬 상위 5종목까지만 검증한다. 연구 단계는 총 12초이며 예산을 넘은 소스는 BUDGET_EXCEEDED로 남긴다.
- 정배열은 MA5 > MA20 > MA60이고 완료 일봉 60개가 필요하다. 돌파는 최근 완료 일봉의 고가가 이전 20개 완료 일봉의 고가 최대값을 넘는 경우다.
- 거래량 배수는 최근 완료 일봉 거래량을 최근 20개 완료 일봉 평균으로 나눈 값이며 평균에 최근 일봉을 포함한다. 기술 관측일은 DATE_ONLY로 제공한다.
- 장중 가집계는 ESTIMATE_UNDATED로 표시한다. 결산년월은 공시 발표일이 아니며 재무 원수치의 단위는 UNCONFIRMED로 유지한다.
- 기본 체결 구독은 최대 20종목, 추가 시장/호가/프로그램은 최대 2종목으로 제한한다. 계정의 계약상 한도와 샘플의 구독 제한을 같은 것으로 간주하지 않는다.
- 기본 체결은 구독 승인 후 30초 안의 실제 거래일·시각을 가진 틱만 사용한다. 날짜 없는 보조 메시지는 원 거래일이 확인된 체결로 표시하지 않는다. NXT 연장 시간은 별도 확인 전 활성화하지 않는다.

예시 검색: `PER 15.5배 이하 PBR 1.2 이하`, `이평선 정배열 20일 돌파`, `거래량 20일 평균 대비 2배 이상`. 실제 자료가 미확인되면 UNAVAILABLE이며 조건을 생략해 다른 종목을 표시하지 않는다.

## 기존 텔레그램 예약 연결

예약 분석은 평일 거래일의 **08:50 / 11:50 / 14:50 KST**에 기존 4개 모드를 실행한다. 기존 개인·채널 대상 설정을 사용한다. 별도 테스트 발송이나 새로운 수신자를 추가하지 않는다.

08:40 / 11:40 / 14:40에는 새 소스를 준비한다. 분석 단계의 sourceExpansion 메타데이터는 필터·저장·조회 경로에서 보존되며 추가자료를 확인한 조회 후보 수와 조회 후보 중 실제 체결 확인 수를 안내한다. 이 수치는 최종 추천 종목 전체의 검증 건수가 아니다. Telegram의 `ok: true` 응답만 전송 성공으로 기록한다.

서버 재시작으로 유효 캐시를 복구할 때 이미 게시한 분석을 재전송하지 않는다. startup 보충과 cron은 같은 실행 가드를 공유해 동시 실행을 막는다. 08:50은 장전이므로 실시간 체결 확인 0건 또는 MARKET_CLOSED가 정상이며 09:00 첫 틱 확인을 미리 성공으로 기록하지 않는다.

## 사용자가 직접 준비할 항목

1. KIS 정보이용·제휴 권한이 유료 회원 서비스의 시세 제공 범위를 포함하는지 확인한다. 기존 답변은 ‘확인 필요’이며 확인 완료로 임의 변경하지 않는다.
2. eFriend Plus [0110]에서 원하는 조건식을 작성하고 **사용자조건 서버저장**을 완료한다. API는 로컬 HTS 조건식만으로 동작하지 않는다.
3. 확인 후 운영용 `backend/.env` 편집기에 `BITMAN_KIS_HTS_ID`를 입력한다. 키나 ID를 채팅에 보내지 않는다. 기존 KIS App Key/App Secret은 재입력할 필요가 없다.
4. 권한이 확보된 경우에만 `BITMAN_KIS_SOURCE_EXPANSION_ENABLED=true`, `BITMAN_KIS_SOURCE_EXPANSION_LICENSED=true`로 설정하고 운영 서버를 재시작한다. 이후 관리자 > 시스템 상태의 `sourceExpansion`에서 각 소스 상태를 확인한다.
