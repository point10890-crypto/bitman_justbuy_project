# BitMan 구독 플랜과 신청 흐름

2026-10-11 사용자 요청: 6개월 150,000원 플랜을 추가하고 사용자가 구독 신청까지 쉽게 이동하도록 개선한다.

| 플랜 | 이용 기간 | 입금 금액 |
|---|---|---|
| MONTHLY | 1개월 | 30,000원 |
| SIX_MONTHS | 6개월 | 150,000원 |

6개월 플랜은 월 25,000원꼴이며 월간 이용권 6회(180,000원)보다 30,000원 적다. 입금은 150,000원 일시 납부이며 기존 계좌 입금·관리자 확인 방식을 사용한다. 기간은 기존 월간과 동일한 달력 월 기준이다.

- 소개 화면과 공개 `/subscribe`에서 플랜을 비교·선택한다. 가입·로그인 링크의 `plan` query로 선택을 유지하고, 인증 후 해당 구독 신청 화면으로 이어진다.
- 신청 화면에서 플랜과 입금 금액, 계좌, 입금자명과 다음 단계를 확인한다. 서버 카탈로그의 기간·가격이 맞는지 확인한 뒤 신청한다.
- 신청 후 승인 대기 화면은 URL 대신 서버에 저장된 신청 플랜·금액을 표시한다. 입금 확인 후 승인되면 앱을 이용한다.
- 활성 PRO는 기존 이용 기간을 유지하면서 연장을 신청한다. 승인 시 기존 종료일과 오늘 중 늦은 날부터 선택한 기간만큼 연장한다. 반려 시 기존 승인 플랜과 유효한 이용권을 유지한다.
- 관리자 승인 목록과 구독 관리, 마이페이지에 실제 플랜을 표시한다. 관리자 회원 편집의 대기→PRO 전환도 같은 승인 계산을 사용한다.

## 서버 계약

- `GET /api/subscription/plans`: 공개 가격표 `[{id, label, months, price}]`.
- `POST /api/subscription/apply`: 인증 필요. `{depositorName, plan}`. 서버 enum으로 기간과 정가를 정하며 클라이언트의 금액 입력을 신뢰하지 않는다.
- `plan`을 보내지 않는 구버전 신청은 월간으로 처리한다. 잘못된 값은 400이다.
- `UserDto.subscriptionPlan`: 마지막 승인 플랜. `requestedSubscriptionPlan`: 승인 대기 중인 신청 플랜. 활성 연장 신청이 기존 플랜을 덮어쓰지 않도록 분리한다.
- Flyway는 nullable 컬럼 두 개만 추가한다. 기존 회원 상태·기간·승인 이력은 갱신하지 않는다. 구버전 대기 신청의 null 플랜은 월간으로 승인한다.
- 기간 제한 없는 기존 PRO와 관리자 계정은 추가 입금·신청 화면을 열지 않고 앱 홈으로 이동한다. 서버에서도 구독 신청을 거절하여 기존 권한을 유지한다.

## 6개월 플랜 최초 검증

로컬 워크플로우 검증은 전용 가상 회원·입금자명을 사용하며 실제 구독 신청·입금·운영 회원 변경을 수행하지 않았다.

- 프론트엔드 전체 테스트 53개 통과. 공개 화면부터 가입·로그인, 신청, 승인 후 앱 이동, 기존 PRO 연장, 서버 가격 불일치 차단·재확인, 무기한 PRO 보호를 포함한다.
- 백엔드 전체 테스트 259개 통과. 6개월 승인·연장·반려, 구버전 월간 호환, 잘못된 플랜 거절, 공개 카탈로그와 신청 인증, 기존 회원을 보존하는 마이그레이션, 무기한 PRO·관리자 보호를 포함한다.
- TypeScript 검사와 Vite 프로덕션 빌드 통과. JS `index-dyMR2R4b.js`, CSS `index-BaO4lied.css`.
- 로컬 브라우저에서 320px/390px 모바일과 1440px 데스크톱을 확인했다. 가입·로그인 후 `SIX_MONTHS` 유지, 신청 후 6개월·150,000원 대기 표시, 승인 확인 후 홈 이동, 활성 PRO의 연장 신청 후 마이페이지 이동을 확인했다.
- PWA 캐시 버전: `bitman-v20261011-subscription-r1`.
- MiniPC 배포 스크립트에서 백엔드 테스트와 JAR 빌드, 운영 DB·JAR 백업, 재시작 후 상태 확인을 완료했다. MiniPC 로컬과 공개 `/api/health` 모두 `status=ok`, `service=justbuy-api`다.
- 운영 `https://api.bit-man.net/api/subscription/plans`는 월간 30,000원과 6개월 150,000원을 반환한다.
- Cloudflare Pages main `0f057c34`와 production `639f36db` 배포 완료. 기본 Pages 주소, production 별칭, Spring static 모두 같은 JS/CSS 파일과 새 SW 캐시 버전을 제공한다.
- 실제 `https://bitman-justbuy.pages.dev/`의 6개월 요금 카드에서 `/subscribe?plan=SIX_MONTHS`로 이동했다. 인앱 브라우저에서 선택된 6개월과 150,000원, `/login?plan=SIX_MONTHS` 및 `/register?plan=SIX_MONTHS` 연결을 확인했다. 운영 계정 생성·구독 신청·입금은 수행하지 않았다.
- 로컬 테스트 전용 진입 파일과 서버는 정리했으며 배포 산출물에 포함하지 않았다.

## 승인대기 입금 안내 개선

2026-10-11 추가 요청에 따라 신규 구독의 승인대기 페이지와 연장 신청 후 마이페이지에 동일한 신청·입금 정보 카드를 표시한다.

- 서버에 저장된 신청 플랜의 기간과 입금 금액, 은행, 계좌번호, 예금주, 입금자명을 한 카드에서 확인한다. URL의 플랜 선택이나 현재 승인된 이용권으로 신청 금액을 계산하지 않는다.
- 은행 정보는 `SUBSCRIPTION_BANK_ACCOUNT` 하나로 공유하며 기존 국민은행 계좌와 예금주는 변경하지 않았다. 계좌번호만 복사하는 버튼과 복사 실패 안내를 제공한다.
- 이미 입금한 회원에게는 추가 입금 없이 승인 대기하라는 안내를 표시한다.
- 마이페이지는 대기 중 30초마다 회원 상태를 확인하며, 새로고침 버튼으로 즉시 확인할 수 있다. 승인·반려 후 입금 카드가 제거되며 기존 유효 이용 기간은 유지한다.
- 관리자·무기한 PRO·대기 신청이 없는 일반 PRO에게는 대기용 입금 카드를 표시하지 않는다.
- 프론트엔드 전체 테스트 57개 통과. 신규 대기·연장 대기·기존 플랜과 다른 신청 금액·승인 후 카드 제거를 포함한다.
- TypeScript·Vite 빌드 통과. JS `index-BsE4ooyr.js`, CSS `index-BhueEXHq.css`, SW 캐시 `bitman-v20261011-subscription-pending-r2`.
- 로컬 브라우저에서 실제 페이지·AuthProvider와 가상 응답을 사용해 320px/390px 화면, 계좌 복사, 기존 월간 대기 30,000원, 6개월 연장 대기 150,000원과 기존 만료일 유지, 새로고침 후 입금 안내 제거를 확인했다. 실제 API 호출·회원 정보 접근·입금은 하지 않았다.
- MiniPC 배포에서 백엔드 259개 테스트 및 JAR 빌드 통과, DB·JAR 백업 후 재시작 완료. 로컬·공개 API 상태는 모두 `ok`다.
- Cloudflare Pages main `4f58e34f`, production `a134e44b` 배포 완료. Pages 기본 주소·production 별칭·Spring static의 JS/CSS 해시와 새 SW 버전을 확인했다.
- 실제 브라우저의 공개 구독 페이지와 사용자 홈페이지가 `index-BsE4ooyr.js`를 로드하며 6개월 150,000원과 구독 연결을 유지한다. 인증이 필요한 승인대기·연장대기 화면은 가상 응답으로 검증했으며 운영 회원의 신청·승인 상태는 조작하지 않았다.
- 임시 로컬 미리보기 파일과 서버는 정리했고 배포 산출물에 포함하지 않았다.
